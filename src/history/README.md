# history — undo/redo 스택

## S6 — `History<T>` (`history.ts`)

### 왜 필요한가
- Phase 1에서 사용자가 Patch를 누를 때마다 "그 시점의 VDOM"을 기록해 두면, 뒤로/앞으로 버튼으로 어느 시점이든 되돌릴 수 있다.
- VDOM은 일반 객체라서 스냅샷을 **복사하지 않고 참조만 보관**해도 된다. 실제 DOM 전체를 복사해 두는 것보다 훨씬 싸다.

### 동작 원리
상태 배열 `states`와 현재 위치 `cursor`로 구성된다.

```
states: [s0, s1, s2, s3]
                 ▲ cursor=1   → canUndo, canRedo 둘 다 true
```
- `push(state)`: `cursor` 뒤의 상태(되돌려 둔 미래)를 잘라 버리고 새 상태를 붙인 뒤 `cursor`를 끝으로 옮긴다. undo한 뒤 새로 편집하면 이전 redo 기록이 사라지는, 일반적인 에디터의 동작이다.
- `undo()` / `redo()`: `cursor`를 한 칸 옮기고 그 상태를 돌려준다.
- `canUndo = cursor > 0`, `canRedo = cursor < size - 1`. UI는 이 두 값으로 버튼의 `disabled`를 정한다.

### 설계 결정
- **제네릭.** `History<T>`는 상태가 무엇인지 모른다. Phase 1에서는 VNode를 담지만, 다른 곳에서도 재사용할 수 있다.
- **경계에서 에러를 던지지 않는다.** 처음에서 `undo()`, 끝에서 `redo()`를 호출하면 현재 상태를 그대로 돌려준다. 버튼 비활성화가 1차 방어이고, 키보드 단축키 같은 다른 경로에서 실수로 호출해도 안전하다.
- **불변 스냅샷 전제.** 참조를 그대로 보관하므로, 넣은 상태를 나중에 변형하면 기록이 오염된다. VDOM은 `diff`/`patch`가 변형하지 않는다(테스트로 보장).
- **`limit` 옵션.** 기록이 무한히 늘지 않도록 최대 개수를 정할 수 있다. 넘으면 가장 오래된 상태부터 버리고 `cursor`를 맞춘다. 기본은 제한 없음이다.

### 한계 (의도적)
- 상태 전체를 저장하는 방식이라, 상태가 매우 크면 메모리를 쓴다. 변경분(패치)만 저장해 역패치로 되돌리는 방법도 있지만, 구현이 훨씬 복잡하고 VDOM 스냅샷은 구조를 공유할 수 있어 지금은 단순함을 택했다.
